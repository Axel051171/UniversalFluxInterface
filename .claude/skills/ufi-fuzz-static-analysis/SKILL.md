# UFI Fuzzing and Static Analysis

## Purpose

Describes how production firmware units are fuzzed on the host with LibFuzzer and analysed with
the Clang path-sensitive analyzer, and what has to be touched when a module, a parser or a driver
call is added. Both gates compile the files in `firmware/src` unchanged; HAL-bound units are built
against declaration-only headers in `firmware/tests/hal_stub` and generated doubles.

## Invariants and traps

- **Every analyzer report is an error.** `check_static.py` passes `-analyzer-werror`; there is no
  suppression list. Fix the code path (or the bound the analyzer cannot see), do not silence it.
- **A new `firmware/src/ufi_*.c` is analysed automatically** in the stub group (glob minus `PURE`
  minus `NEEDS_REAL_HAL`). It must therefore compile against `firmware/tests/hal_stub`:
  `stm32h7xx_hal.h` declares only GPIO, a few TIM/ADC/DWT names, UID, tick, delay, reset, cache
  and PRIMASK helpers; `ff.h`, `usbd_def.h`, `usbd_cdc.h` stand in for FatFs and the USB library.
  Anything else needs a declaration added there, or the module goes into `NEEDS_REAL_HAL` with a
  comment saying which peripheral forces it.
- **`--compile-commands` mode counts files.** It must analyse exactly as many translation units as
  there are `*.c` in `firmware/src`; a source that exists but is not in `firmware/CMakeLists.txt`
  ends with "Incomplete ARM analysis: n/m project modules".
- **Generated stubs know only return types.** `fuzz_stubs.generate()` never writes output
  parameters and never relates a returned length to a capacity argument. A callee with such a
  contract needs a hand-written double in the harness (see `ufi_file_read`, `ufi_quality_report`,
  `ufi_flux_store` in `fuzz_v2.c`); otherwise the fuzzer reports an overflow that belongs to the
  stub, not to the firmware. Symbols the harness defines are left alone by the generator.
- **Prototypes must live in a header.** Stubs are derived from `firmware/include/*.h` and
  `hal_stub/*.h` (not from `iec_nib.h`, `usbd_conf.h`, `stm32h7xx_hal_conf.h`, `ffconf.h`). A
  function or variable declared `extern` only inside a `.c` file stops the build with
  "fuzz_<target>: no prototype found for <symbol>". Move the declaration to a header or add the
  symbol to `extra` in the target's `STUBBED` entry.
- **The same message appears for a new libc call.** Unresolved names are tolerated only if they
  are in `LIBC` or start with one of `LIBC_PREFIXES` in `run_fuzz.py`; add the function there.
- **Time must advance in the harness.** `HAL_GetTick` / `HAL_Delay` doubles increment a counter
  (and occasionally jump 20 s) so that firmware timeouts end; a wait loop on a stubbed flag without
  a tick-based exit shows up as a libFuzzer timeout (5 s per input).
- **UBSan runs only off Windows.** `sanitizer_flags()` uses `fuzzer,address` on win32 and
  `fuzzer,address,undefined` elsewhere. An undefined shift in `ufi_v2_event()` was found only by
  the CI run (commit 97a96dc). Local Windows runs do not replace the Linux run.
- **The corpus is not versioned.** `fuzz_*_corpus/`, logs and artifacts live in the ignored
  `firmware/tests/build/`; CI starts from the seeds in `run_fuzz.py` every time. A finding is
  preserved only by adding a seed tuple entry (and normally a deterministic test, see
  ufi-test-gate). Never commit `crash-*`, `leak-*`, `timeout-*`, `oom-*` files (commit 129e5a5).
- **`--target` choices are a literal tuple** in `main()`, separate from the `TARGETS` dict. A new
  target must be added to both; `all` iterates `TARGETS`.
- Docs lag the code: `README.md` names 34 analysed modules and the usage line in the
  `run_fuzz.py` docstring lists four targets. The lists in the scripts and the counts they print
  are authoritative.

## Fuzz targets

| Target | Harness | Production code | Asserted beyond ASan/UBSan/timeout |
|---|---|---|---|
| `parsers` | `fuzz_parsers.c` | `ufi_hfe_v3`, `ufi_write_codec`, `ufi_image`, `ufi_raw_verify`, `ufi_job`, `ufi_resources` | Rejected job/resource calls leave state unchanged; `hfe_v3_decode` keeps guard words, 3..512 intervals of 220 ticks or more, sum within `report.ticks`; `compact_feed` whole vs byte-wise gives identical output; HFEv3 encode/decode round trip; `raw_profile_build` from deltas and from times agree |
| `protection` | `fuzz_protection.c` | `ufi_protection`, `ufi_quality`, `ufi_mfm`, `ufi_verify`, `ufi_compare`, `ufi_metrics` | Rejected options unchanged; second `protection_finish` changes nothing; at most 48 evidence entries; `protection_pack` stays within capacity |
| `v2` | `fuzz_v2.c` | whole `ufi_v2.c` + real job, resources, cancel, capabilities, media, metrics, write codec, quality, protection, LAN status/cfg | Every frame handed to `ufi_native_tx_*` is well formed (55 AA, type, length, CRC); clean state after reset; owner and route valid at the end |
| `gw` | `fuzz_gw.c` | whole `ufi_gw.c` + resources, cancel | Every transmit is non-null, 1..512 bytes; no hang |
| `sd` | `fuzz_sd.c` | whole `ufi_dump.c` + image, HFE, MFM, verify, quality, protection, compare, codec | FatFs calls respect open/closed state and pointers; `f_mkfs` is never called; no dump stays active; output bounded |
| `drive` | `fuzz_drive.c` | whole `ufi_drive.c` + drive_extra, media, capabilities, verify, mac | Without an injected sensor fault: successful seek leaves module and head model on the same track, recalibrate ends on track 0, stored profile reads back |
| `usb` | `fuzz_usb.c` | whole `ufi_usb.c` (legacy v1 commands, transmit helpers, mode switch); all drivers generated stubs | Every v1 reply = header + exactly `length` <= 64 bytes; nothing transmitted in the mass storage modes; packets handed over in exact-size heap blocks. Does not see reuse of stale bytes inside the static 64-byte command buffer |
| `floppy` | `fuzz_floppy.c` | whole `ufi_floppy.c` + real `ufi_mfm` (built `fast`: -O2, no instrumentation) against a disk model: captures encoded from the model, writes decoded back into it | Tracks stay inside 84 x 2; an undisturbed disk is recognised or refused by the format / boot sector rule and reports that size; a successful read returns the last accepted data; after a successful `ufi_floppy_end()` every accepted write is on the disk. Script bytes come from the input's end, stubs have their own generator. `FUZZ_TRACE=1` prints one line per operation |
| `lan` | `fuzz_lan.c` | `ufi_lan_cfg`, `ufi_net`, `ufi_w5500`, `ufi_sha256`, `ufi_lan_session`, `ufi_lan_status` on `w5500_fake.h` | Config bounds and usable addresses; DHCP reply type; address state machine; session frames with CRC; discovery answer is 32 bytes "UFI!" |

`parsers`, `protection` and `lan` link HAL-free sources directly. `v2`, `gw`, `sd`, `drive` go
through `build_stubbed()`: units and `real` modules are compiled with `STUB_FLAGS` (hal_stub
include path, `__packed`, version defines) and `-w`; the harness with `-Wall -Wextra -Werror`;
`fuzz_stubs.generate()` runs `llvm-nm` over the objects and writes `stubs.c` (built as C23) for
every undefined symbol.

Oracle (`fuzz_oracle.h`, implemented in each stubbed harness): `fuzz_byte()` consumes the input
from its tail, then continues with a xorshift generator; `fuzz_u32()` returns small numbers, values
near 0xFFFFFFFF, multiples of 256 or single bits; `fuzz_err()` is 0 mostly, otherwise -1..-21;
`fuzz_bit()`; `fuzz_zero_buffer()` is 8 KiB zeroed per input; `fuzz_string()` is "". Generated
stubs map `int` to `fuzz_err`, `bool` to `fuzz_bit`, other scalars to `fuzz_u32`, pointers to the
zero buffer, structs to zero, `void` to an empty body; `extern` data gets a zero definition.

## Static analysis groups

| Group | Selection in `check_static.py` | Headers |
|---|---|---|
| HAL-independent | tuple `PURE` | `firmware/include` only; `ufi_firmware.h` / `board.h` pull `stm32h7xx_hal.h`, which is not found here - that failure is the point |
| Stub group | every other `ufi_*.c` not in `NEEDS_REAL_HAL` | plus `firmware/tests/hal_stub` (`STUB_FLAGS`) |
| Not covered portably | set `NEEDS_REAL_HAL` (board, clock, USB, flux, PSRAM, SD, write, LAN glue, ...) | only in `--compile-commands` mode |
| ARM mode | every `.c` directly in `firmware/src` from `compile_commands.json`, including `board_headless.c`, `stm32h7xx_it.c`, `usbd_*.c` | real Cube/USB/FatFs headers, `-I`/`-D` of the build, `--target=arm-none-eabi -mcpu=cortex-m7`, newlib from `arm-none-eabi-gcc` |

Neither mode proves hardware timing; vendor sources are not analysed.

## Procedures

### Add a new firmware module to both gates

1. HAL-free module: add its stem to `PURE`. HAL-bound: run `python firmware/tools/check_static.py`
   and add missing declarations to `hal_stub/stm32h7xx_hal.h` (declarations and register structs
   backed by `stub_*` objects only, no behaviour). Use `NEEDS_REAL_HAL` only when the module needs
   real HAL peripheral types (the comment in the script names I2C, RCC, TIM8, SPI3, TIM1).
2. Add the file to `firmware/CMakeLists.txt`, build, and run the ARM mode (see Examples).
3. If a fuzzed unit (`ufi_v2.c`, `ufi_gw.c`, `ufi_dump.c`, `ufi_drive.c`) calls the module:
   decide per target whether it runs for real (append the stem to `real` in `STUBBED`; it must
   compile with `STUB_FLAGS`) or stays stubbed (nothing to do if all prototypes are in headers).
4. For every stubbed callee with an output buffer, an out-parameter the caller reads, or a
   length bounded by an argument: write a double in the harness.
5. Run the affected targets for 60 s or more and read the "generated stubs" line and the tail of
   the log.

### Fuzz a new parser or command

1. HAL-free parser: extend the fitting direct harness. `fuzz_lan.c` and `fuzz_sd.c` select the
   code path with input byte 0 - add the next selector value, keep existing values stable so that
   stored corpora stay meaningful. Add the source to `build_parsers()` / `LAN_SOURCES` if new.
2. State an invariant with `assert`, not just "does not crash": bounds of every output field,
   rejection leaves state untouched, round trip, chunked vs whole input gives equal results.
3. New v2 command: no harness change is needed for reachability (records carry any command byte),
   but add a seed to `V2_SEEDS` built with `record(flags, cmd, seq, payload)` that reaches the
   handler with a valid payload; same for `GW_SEEDS` with `gw(cmd, *args)`.
4. Add seeds for each new selector or format to the matching `*_SEEDS` tuple; seeds are rewritten
   into the corpus directory as `seed<i>` on every run.
5. A separate target is justified only for a new whole unit: harness file with
   `LLVMFuzzerTestOneInput`, the seven oracle functions and per-input state reset; `STUBBED` entry
   (`harness`, `units`, `real`, `extra`) or a `build_<name>()` function; `TARGETS` entry
   `(build, seeds, corpus dir, max_len)`; the `--target` choices; the replay list in
   `firmware/tests/coverage.py`; the module docstring; a note in `docs/Implementation_Status.md`.

### Handle a finding

1. Read `firmware/tests/build/<target>_fuzz_result.log`; the artifact is
   `firmware/tests/build/<target>-crash-<hash>` (or `-timeout-`, `-oom-`, `-leak-`).
2. Reproduce by passing the artifact to the built fuzzer binary; `FUZZ_TRACE=1` makes
   `fuzz_drive` print one line per operation and modelled step.
3. Decide whether the firmware or the double is wrong (unbounded stub length, missing
   out-parameter, time not advancing). Fix firmware in `firmware/src`; fix doubles in the harness.
4. Add the minimal input as a seed and a deterministic regression (ufi-test-gate), rerun the
   target and `python firmware/tests/check_all.py`.

## Examples

```bash
python firmware/tools/check_static.py                 # PURE + stub group, host clang
cmake -S firmware -B firmware/build -G Ninja -DSTM32CUBE_PATH=$HOME/STM32CubeH7
cmake --build firmware/build
python firmware/tools/check_static.py --compile-commands firmware/build/compile_commands.json

python firmware/tests/run_fuzz.py --seconds 30        # all seven targets, as CI runs it
python firmware/tests/run_fuzz.py --target v2 --seconds 300
python firmware/tests/run_fuzz.py --target sd --replay   # stored corpus once, no mutation
firmware/tests/build/fuzz_v2 firmware/tests/build/v2-crash-<hash>           # reproduce (Linux)
FUZZ_TRACE=1 firmware/tests/build/fuzz_drive firmware/tests/build/drive-crash-<hash>
```

Hand-written double for a callee whose result is bounded by an argument (`fuzz_v2.c`):

```c
int ufi_file_read(const char* name, uint32_t offset, uint8_t* out, uint16_t len, uint16_t* got)
{
    (void)name; (void)offset;
    *got = (uint16_t)(fuzz_u16() % (len + 1u));
    memset(out, 0x5A, *got);
    return fuzz_err();
}
```

Symbol without a header prototype, declared in the target's `STUBBED` entry (`run_fuzz.py`):

```python
extra={'g_capture': ('ufi_firmware.h', 'capture_context_t g_capture;'), **LINKER_SYMBOLS}
```

Done criterion: `python firmware/tools/check_static.py` prints "Static analysis passed: ...", the
ARM mode prints "Static ARM analysis passed: all N project modules ...", and `run_fuzz.py` for
every touched target returns 0 with no artifact written. CI (`.github/workflows/firmware.yml`):
job `offline-tests` runs `check_static.py` first and `run_fuzz.py --seconds 30` last (clang,
Ubuntu 24.04, ASan and UBSan); job `build` runs the `--compile-commands` mode after the ARM build.

## Prerequisites

- clang with the libFuzzer and sanitizer runtimes and `llvm-nm` (found beside clang, through the
  resolved link, or as `llvm-nm-<N>`); `CC` selects the compiler for `run_fuzz.py`, while
  `check_static.py` always takes `clang` from PATH.
- ARM mode: `arm-none-eabi-gcc` with newlib headers on PATH, STM32CubeH7 v1.11.0, and a configured
  build directory (`CMAKE_EXPORT_COMPILE_COMMANDS` is switched on in `firmware/CMakeLists.txt`).
- `--seconds` accepts 1..3600 per target; each run has `-max_len` from `TARGETS`, `-timeout=5`
  and the fixed `-seed=12345`.
- Windows: `fuzzer_env()` puts the clang resource directory `lib/windows` on PATH for the run;
  starting a fuzzer binary by hand needs the same directory on PATH.

## Limitations

- Stubbed drivers return arbitrary values without hardware semantics; sequences a real driver
  cannot produce are explored, and real timing, DMA and interrupt interleaving are not.
- `ufi_usb.c`, `ufi_flux.c`, `ufi_write.c`, `ufi_psram.c`, `ufi_sd.c`, `ufi_msc.c` and the other
  `NEEDS_REAL_HAL` modules have no fuzz target and are analysed only in ARM mode.
- 30 s per target in CI is a smoke run from seeds; deeper exploration needs long local runs whose
  corpus stays on the local machine.
- `coverage.py` replays only v2, gw, sd and drive; parsers, protection and lan do not contribute
  to the coverage numbers.

## Troubleshooting

| Problem | Cause | Fix |
|---|---|---|
| "fuzz_v2: no prototype found for X" | X is declared only in a `.c` file, in a skipped header, or is a libc function new to the firmware | Move the prototype to a header in `firmware/include`, add X to `extra` of the `STUBBED` entry, or add the libc name to `LIBC` |
| ASan overflow inside firmware right after a stubbed call returns a length | Generic stub returned an unbounded count or left an out-parameter unset | Write a bounded double in the harness, as for `ufi_file_dir` |
| libFuzzer "timeout" artifact | Firmware loop waits on a stubbed condition and time does not advance, or a real unbounded loop | Check the tick double first; if time advances and the loop still spins, it is a firmware bug |
| "llvm-nm not found next to ..." | LLVM tools missing or only versioned names installed outside PATH | Install the LLVM tools matching clang; `llvm_tool()` tries `llvm-nm-30` down to `llvm-nm-10` |
| Fuzzer `.exe` does not start on Windows when launched by hand | Sanitizer runtime DLL not on PATH (`run_fuzz.py` adds it in `fuzzer_env()`) | Start through `run_fuzz.py` or add `<clang -print-resource-dir>/lib/windows` to PATH |
| CI fuzz step red with "runtime error: ..." but local Windows run green | UBSan is active only on Linux | Reproduce under WSL or Linux with clang, fix the undefined behaviour in `firmware/src` |
| `check_static.py`: "file not found" for a HAL header in the first group | A module listed in `PURE` includes `ufi_firmware.h` or a HAL header | Remove the include or take the module out of `PURE` |
| `check_static.py`: unknown type or undeclared identifier in the stub group | New HAL symbol not declared in `hal_stub` | Add the declaration to the stub header, or list the module in `NEEDS_REAL_HAL` with the reason |
| "Incomplete ARM analysis: n/m project modules" | A `.c` in `firmware/src` is missing from the CMake target, or `compile_commands.json` is stale | Add the source to `firmware/CMakeLists.txt` and reconfigure |
| "Newlib headers missing" / "ARM header analysis requires arm-none-eabi-gcc" | Toolchain not on PATH or installed without newlib | Install `gcc-arm-none-eabi` and `libnewlib-arm-none-eabi` as the CI does |
| Analyzer reports a garbage read or null dereference in code that is correct on the target | Bound not visible on the analysed path | Make the bound explicit in the code (range check before use); there is no suppression mechanism |
